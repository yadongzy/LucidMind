# 第三条：代码边界（硬性上限）

| 文件类型 | 行数上限 | 超出处理 |
|---------|---------|---------|
| brain.py | 500 行 | 拆分为 mixin 或委托给 Port |
| brain_*.py (mixin) | 300 行 | 按职责拆分 |
| 每个 Port 接口 | 50 行 | 职责不单一，需拆分 |
| 每个 Adapter | 300 行 | 拆分为子模块 |
| api/main.py | 250 行 | 拆分为 routes/ |
| 单个测试文件 | 300 行 | 按功能拆分 |
| 前端 JS (主文件) | 500 行 | 拆分为模块 |
| 前端 CSS | 600 行 | 拆分为模块 |
| scripts/ 脚本 | 250 行 | 拆分为多个脚本 |
| 配置文件 (.env等) | 50 行 | 拆分或使用环境变量 |
| SOUL.md | 200 行 | 精简核心人格 |

## 禁止硬编码大脑行为（铁律）

**不要在代码中给大脑写死行为指令。** 大脑应该通过学习机制自己掌握能力，而不是被代码束缚。

- ❌ 在 SOUL.md 或代码中写死"用工具A不要用工具B"
- ❌ 用 if/else 硬编码特定场景的处理逻辑
- ✅ 通过经验库（lessons.json）注入知识，让大脑自己检索和应用
- ✅ 通过用户教学（"记住/以后/下次"）让大脑学会新能力
- ✅ 通过反思机制（说"不会"后自动反思）让大脑自我进化
- ✅ 给大脑留出发挥空间，允许它用自己的方式解决问题
