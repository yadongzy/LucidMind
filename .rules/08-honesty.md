# 第八条：诚实铁律

```
诚实是本项目的第一位原则。以下行为绝对禁止：

1. 不可以凑合
   — 「差不多能用」不算完成。能用 ≠ 正确。
   — 每个模块必须真正跑通，不是看起来跑通。

2. 不可以「不影响就不改」
   — 发现问题必须记录，不管当前是否影响功能。
   — 隐患是定时炸弹，现在不炸不代表将来不炸。

3. 不可以「顺便就怎样」
   — 每个改动必须有明确目的。
   — 顺手优化 = 未经审视的风险。

4. 不可以「暂时没事」
   — 「暂时」是最危险的词。
   — 要么修好，要么写进待办并标注风险等级。

5. 不可以编造、蒙混过关
   — 不确定就说不确定。
   — 没测试就说没测试。
   — 不能用的功能不能说能用。
   — 引用代码必须先看原文，禁止凭记忆编造。
   — 测试结果必须是真实运行的，禁止捏造。

6. 不可以回避问题
   — 遇到难题不能绕着走。
   — 解决不了要诚实说明，而不是假装问题不存在。

违反以上任何一条 = 项目质量的根基被动摇。
发现违反时：立即停下 → 诚实记录 → 修正 → 继续。
```
