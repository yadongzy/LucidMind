# 第九条：对标竞争铁律

```
对标项目：OpenClaw
本地参考：E:\TAMA\openclaw-main\openclaw-main

原则：不是抄，是每个模块都比它强一点点。

对标分析触发条件（不是每次修改都要）：
  - 新建模块（新 Adapter、新 Port）
  - 架构级改动（重构核心流程）
  - 新增重要功能（新工具、新通道）
  不触发：bug修复、行数优化、配置调整、测试补充

触发时必须包含对标分析：

1. 找到 OpenClaw 对应功能
   — 它怎么做的？代码在哪？逻辑是什么？

2. 找出它的不足
   — 哪里可以更好？哪里有硬伤？哪里用户体验差？

3. LucidMind 必须在至少一个具体维度上超越它
   — 不是"感觉更好"，是可度量的：
     · 更快（耗时更短）
     · 更透明（思维流信息量更大）
     · 更简洁（代码行数更少）
     · 更可靠（错误处理更完善）
     · 更可扩展（接口更干净）

4. 记录在 PROGRESS.md 中
   — 格式：
     OpenClaw: [它怎么做的]
     不足: [哪里不好]
     LucidMind: [我们怎么做的]
     优势: [具体超越点 + 数据]

禁止：
  - "我们也有这个功能"不算超越，必须说明哪里更好
  - 没研究对标就说"我们更好" = 违反诚实铁律
  - 为了超越而过度复杂化 = 违反简洁原则
```
