# 第十二条：最优解优先

```
执行任务过程中发现更好的方案时，在不违反现有规则的前提下，
以最优方式为先，无需额外确认。

原则：
1. 发现最优解 → 直接采用（不走弯路）
2. 最优解不得违反任何编号更小的规则
3. 采用后在对话中简要说明：原方案 → 最优方案 → 为什么更好

典型场景：
  - 文件行数将超限 → 拆分为独立模块（如 api/sessions.py）
  - 重复代码 → 提取为公共方法
  - 性能瓶颈 → 换更高效的算法/数据结构
  - 架构更清晰的写法 → 直接采用

边界：
  - 最优解涉及修改 [LOCKED] 文件 → 仍需走第五条流程
  - 最优解涉及新增 Port → 仍需走第六条流程
  - 不确定是否真的更优 → 先说明再执行
```
