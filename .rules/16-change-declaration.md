# 第十六条：变更声明制（先说后做）

```
任何代码修改前必须声明，防止"顺便就改了"的问题。

1. 声明内容（修改前必须告知用户）
   - 要改什么文件
   - 为什么要改（目的）
   - 改动范围（新增/修改/删除多少行）
   - 是否涉及核心文件（见第十五条）

2. 操作分级

   免确认（直接执行）：
   - 新建 adapters/ 下的 Adapter 文件
   - 新建 scripts/ 下的脚本
   - 新建 docs/ 下的文档
   - 新建 tests/ 下的测试文件
   - 修改 tests/ 下的测试文件（不能删除/弱化）

   需声明（简要说明后执行）：
   - 修改非核心的 Adapter 文件
   - 修改配置文件
   - 修改日志相关代码

   需确认（必须等待用户同意）：
   - 修改核心文件（第十五条清单）
   - 删除任何文件
   - 修改前端文件
   - 修改路由/挂载路径
   - 修改 Port 接口签名

3. 紧急修复例外
   - 服务器崩溃等紧急bug可先修后报
   - 但必须事后完整报告：改了什么、为什么、测试结果
   - 紧急修复不得涉及架构变更
```
