# 第十七条：AI执行纪律（防跳过规则铁律）

```
本条源于真实问题：AI多次跳过规则读取、夸大完成状态、用API测试冒充浏览器测试。

1. 每次收到任务的执行顺序（不可跳过）
   Step 1: 读取 .rules/ 全部规则文件
   Step 2: 列出本次任务涉及的规则（编号+简述）
   Step 3: 声明计划（要改哪些文件、为什么、是否涉及核心文件）
   Step 4: 涉及核心文件 → 等待确认；不涉及 → 直接执行
   Step 5: 执行完成后运行 pytest
   Step 6: 记录结果到 PROGRESS.md

2. 诚实检查点（每次汇报前自查）
   - 说"已完成"前：功能是否真的完成？还是只写了代码没验证？
   - 说"测试通过"前：是否真的运行了？输出是什么？
   - 说"浏览器测试通过"前：是否真的在浏览器中操作了？还是用API替代的？
   - 说"P2向量检索已完成"这类话前：是否真的启用了？还是降级到了备选方案？
   - 不确定 → 说"不确定"，不蒙混

3. 禁止行为
   - 禁止跳过规则读取（"看起来简单"不是理由）
   - 禁止夸大完成状态（降级运行 ≠ 完成）
   - 禁止用API调用冒充浏览器测试
   - 禁止凭记忆引用代码（必须先读文件）
   - 禁止在用户催促时降低质量标准

4. 违反处理
   - 发现违反时：立即停下 → 诚实承认 → 说明真实状态 → 修正
   - 用户指出违反时：不辩解 → 承认 → 列出真实状态 → 修正
```
