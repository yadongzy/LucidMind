# LucidMind 安全重构发布与恢复手册

本手册适用于 `refactor/safe-execution` 分支引入的任务模型、执行管线、检查点、原子持久化和安全控制面。所有新能力默认关闭，未经观察门禁不得扩大流量。

## 1. 恢复基线

- 基线标签：`baseline/pre-safe-refactor-20260907`
- 重构分支：`refactor/safe-execution`
- Python：3.12.2
- 数据目录、凭据、日志和运行生成物均由 `.gitignore` 排除，不通过 Git 恢复。

代码回退使用 `git revert <commit>` 创建可审计的反向提交。不要用强制重置覆盖工作区。数据恢复必须独立执行，并先隔离当前故障数据。

## 2. 特性开关

| 环境变量 | 默认值 | 作用 | 回退值 |
| --- | --- | --- | --- |
| `LUCIDMIND_SAFE_PIPELINE_ENABLED` | `0` | 选择带持久化 attempt 的安全执行路径 | `0` |
| `LUCIDMIND_SAFE_PIPELINE_SHADOW` | `0` | 比较纯执行计划，不重复外部副作用 | `0` |
| `LUCIDMIND_ORPHAN_RECOVERY_ENABLED` | `0` | 显式允许启动时恢复有检查点的孤儿任务 | `0` |

建议本地放量顺序：先仅开启影子比较，确认无差异后再对隔离测试流量开启安全管线。孤儿恢复单独审批，不随管线开关自动开启。

## 3. 发布前门禁

1. 工作区无非预期修改，`git diff --check` 通过。
2. 运行安全重构聚焦测试集并保存结果。
3. 在项目目录外创建数据快照：

   ```bash
   python scripts/safe_refactor_backup.py create /secure/offsite/lucidmind-backups
   ```

4. 保存输出中的快照路径、SHA-256、恢复文件数和恢复字节数。
5. 确认 `/api/health` 存活检查与 `/api/readiness` 就绪检查符合预期。
6. 确认安全管线、影子模式和孤儿恢复均处于本阶段批准值。

未指定负责人、回滚负责人、告警接收人或观察窗口时，不进入真实灰度。

## 4. 灰度与停止条件

推荐阶段为 1% → 10% → 25% → 50% → 100%，但本仓库当前只提供布尔开关，不实现按比例或按用户路由。真实比例灰度需要由部署层完成。

任一情况出现时立即停止放量：

- 数据丢失、不可解析或出现重复外部副作用。
- 孤儿任务无法从检查点恢复或进入未知状态。
- 错误、超时、延迟、资源占用或队列积压超过已批准阈值。
- 就绪检查持续失败或出现高严重度安全告警。

## 5. 紧急回滚

1. 暂停 Daemon 获取新任务，保留在途任务到达协作式安全点。
2. 将三个开关全部设为 `0` 并重启服务，恢复旧执行路径。
3. 保存 Daemon 状态中的 `safe_control`、`metrics`、孤儿发现和影子差异。
4. 对引入故障的独立提交执行 `git revert <commit>`。
5. 若数据发生变化，复制并隔离当前 `data/`，再验证备份：

   ```bash
   python scripts/safe_refactor_backup.py verify /secure/offsite/lucidmind-backups/lucidmind-data-YYYYMMDD-HHMMSS
   ```

6. 只把已验证归档恢复到新的临时目录，完成文件、任务队列和关键记录核对后，才替换服务数据目录。
7. 运行聚焦测试、健康检查和就绪检查，再决定是否恢复流量。
