## 三、ClawHavoc 供应链攻击事件（关键教训）

| 事实 | 数据 |
|------|------|
| 恶意 skills 数量 | 1,184 个 |
| 占总 registry 比例 | ~20% |
| 攻击载荷 | Atomic macOS Stealer (AMOS)、键盘记录器、RAT |
| 发布门槛 | 仅需 1 周龄 GitHub 账号 |
| 单一攻击者 | "hightower6eu" 一人上传 354 个恶意包 |
| 攻击方式 | 假冒 Prerequisites 指令让用户执行 shell 命令 |
| **新型攻击** | **记忆投毒** — 修改 SOUL.md/MEMORY.md 永久改变 Agent 行为 |

### 对 LucidMind 的直接警告

- LucidMind 也有 SOUL.md 和记忆系统 → **记忆投毒风险完全适用**
- LucidMind 的 skill 是**可执行 Python 代码**（比 OpenClaw 的 SKILL.md 提示词更危险）
- 如果建公开 Hub，同样面临供应链攻击
- OpenClaw 的安全危机证明 **Node.js 不等于安全**

## 八、Agent Skills vs MCP 架构对比 (Friedrichs-IT)

### Agent Skills (OpenClaw 实现)

**优势**:
- 灵活性: 直接代码执行, 无协议开销
- 性能: 进程内执行, 无 IPC 延迟
- 开发速度: 无需 SDK 样板代码
- 自修改: AI 可自动编写和部署 skill

**挑战**:
- 无安全边界: skill 与核心进程共享权限
- 凭证暴露: 共享环境变量
- 供应链风险: 安装时执行任意代码
- 难以审计: 动态代码加载

### MCP

**优势**:
- 进程隔离: 强安全边界
- 凭证作用域: 每个 Server 独立凭证
- 可审计通信: JSON-RPC 消息可记录
- 中立治理: Linux Foundation / AAIF

**挑战**:
- 复杂度: 需要理解 SDK 和协议
- IPC 开销: 跨进程通信增加延迟
- 不够动态: 无法运行时自修改
- 配置负担: 每个 Server 需显式配置

## 九、确认方案: MCP优先 + 本地安全插件混合（双轨制）

### 9.1 架构图

```
┌──────────────────────────────────────────────────────────────┐
│                    LucidMind Brain (Python)                   │
│                                                              │
│  ┌─────────────┐  ┌──────────────┐  ┌─────────────────────┐ │
│  │ 记忆系统     │  │ LLM 适配层    │  │ 工具调度器           │ │
│  │ (memory)    │  │ (fallback)   │  │ (CompositeAdapter)  │ │
│  └─────────────┘  └──────────────┘  └────────┬────────────┘ │
│                                              │              │
│              ┌───────────────────────────────┼──────┐       │
│              │                               │      │       │
│    ┌─────────▼──────────┐      ┌─────────────▼────┐ │       │
│    │  Track 1: 内置工具   │      │ Track 2: MCP工具  │ │       │
│    │  (进程内, <1ms)     │      │ (进程隔离, ~10ms) │ │       │
│    │                    │      │                  │ │       │
│    │  • identity        │      │  • 新安装的skill  │ │       │
│    │  • code_runner     │      │  • 第三方工具     │ │       │
│    │  • web_search      │      │  • 用户贡献工具   │ │       │
│    │  • 已审核信任的skill │      │  • LLM创建的skill │ │       │
│    └────────────────────┘      └──────────────────┘ │       │
│                                                     │       │
│    ┌────────────────────────────────────────────────┘       │
│    │  安全层                                                 │
│    │  • 内置工具: ToolSafetyGuard (已有)                     │
│    │  • MCP工具: 进程隔离 + 凭证作用域 + JSON-RPC审计         │
│    │  • 新skill默认走MCP轨道（不直接exec Python）             │
│    └────────────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────────────┘
```

### 9.2 渐进信任模型（4级）

```
Level 0: 内置 (BUILTIN)
  → 进程内执行, <1ms, 无需审批
  → identity, code_runner, web_search 等

Level 1: 已审核 (AUDITED)
  → 进程内执行, <1ms, 已人工审核代码
  → 用户手动升级: MCP → 内置

Level 2: MCP 隔离 (SANDBOXED)
  → 独立进程, ~10ms, JSON-RPC通信
  → 新安装的Hub skill、LLM创建的skill

Level 3: 远程 (REMOTE)
  → 网络调用, ~100ms, 完全隔离
  → 第三方MCP Server (mcp.so等)
```

### 9.3 新 Skill 安装流程

```
下载 → 安全扫描 → 封装为 MCP Server → Level 2 运行
                                        ↓
                              用户信任后手动升级 → Level 1
                                                   ↓
                                         长期稳定 → Level 0
```

### 9.4 为什么是这个方案（数据支撑）

| 需求 | 方案如何满足 | 数据依据 |
|------|------------|---------|
| 稳定性 | 新skill在MCP进程隔离中运行，崩溃不影响主进程 | ClawHavoc: 进程内执行导致全面失控 |
| 安全 | 新skill默认不在主进程exec | Friedrichs-IT: MCP凭证作用域+可审计 |
| 技能扩展 | 内置+MCP双轨，渐进信任 | AAIF: MCP已由Linux Foundation管理 |
| 执行任何任务 | Python核心保留AI/ML全部能力 | Benchmark: AI/ML领域Python无替代 |
| 手机/手表移植 | MCP协议天然支持远程客户端 | MCP: JSON-RPC over HTTP/WebSocket |
| 无限扩展 | MCP是行业标准，任何语言可写Server | AAIF: AWS/Google/Microsoft支持 |

### 9.5 不改 Node.js 的最终理由

| 证据 | 来源 |
|------|------|
| AI/ML/数据分析在 Node.js 不存在 | DEV.to Benchmark |
| MCP 协议让你无需改语言就能接入任何生态 | AAIF / Anthropic |
| OpenClaw 安全危机证明 Node.js 不等于安全 | ClawHavoc (1,184 恶意包) |
| 可移植性通过协议层解决，不通过语言层 | MCP + WebSocket |
| AIOS (学术界 AI Agent OS) 选择了 Python | COLM 2025 论文 |
