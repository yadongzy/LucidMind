> 版本: v1.0.0 | 创建日期: 2026-02-27
> 方法论: James Whittaker 巡游测试法 + Elisabeth Hendrickson SFDPOT 六维覆盖

## 规则 0: 元规则

**第一规则就是按照规则进行。所有测试必须严格遵循本规则文件。**

---

## 规则 1: 测试流程

1. 每次测试前，先阅读本规则文件
2. 按照《测试方案.md》的步骤顺序逐步执行
3. 每完成一个测试项，在《测试日志.md》中记录结果
4. 当前测试项完成后，才能进入下一步
5. 发现问题时立即记录，不跳过

## 规则 2: 测试标准（通过/失败判定）

### 通过标准 ✅
- 功能按预期工作，无报错
- UI 元素正确显示，无布局错乱
- 按钮点击有正确响应（加载态/结果/错误提示）
- API 返回正确状态码和数据结构
- WebSocket 消息正确收发
- 无控制台 JS 错误（warning 可接受）

### 失败标准 ❌
- 功能不工作或行为异常
- 页面崩溃、白屏、无限加载
- 按钮无响应或响应错误
- API 返回 500 或非预期状态码
- 数据丢失或显示错误
- 控制台有 Error 级别错误

### 待修复标准 ⚠️
- 功能基本可用但有小问题（如样式偏差）
- 非阻塞性的 warning
- 可改进但不影响使用的体验问题

## 规则 3: 版本控制

- 测试通过的模块代码进行**冻结**，未经用户允许不得修改
- 每完成一个大模块测试后，保存版本（v1.0.1, v1.0.2...依此类推）
- 版本号规则: v1.0.X（X 为测试通过的模块序号）

## 规则 4: 问题处理

- 发现 bug 时，先记录到测试日志，不立即修复
- 等当前测试步骤全部完成后，汇总问题
- 修复需经用户确认后才能进行
- 修复后必须重新测试该模块

## 规则 5: 测试环境要求

- 服务端: `uvicorn api.main:app --host 0.0.0.0 --port 8000`
- 前端: 浏览器访问 `http://localhost:8000`
- Python: `/opt/anaconda3/bin/python`
- 测试前确认服务正常启动（/api/health 返回 ok）

## 规则 6: 日志记录格式

每个测试项记录格式:
```
### [模块名] - [测试项名称]
- **时间**: YYYY-MM-DD HH:MM
- **操作**: 具体执行了什么操作
- **预期**: 应该发生什么
- **实际**: 实际发生了什么
- **结果**: ✅ 通过 / ❌ 失败 / ⚠️ 待修复
- **截图/日志**: （如有）
- **备注**: （如有）
```

## 规则 7: 测试覆盖维度（SFDPOT）

每个功能模块从六个维度验证:
- **S (Structure)**: UI 结构是否完整，元素是否齐全
- **F (Function)**: 功能是否按预期工作
- **D (Data)**: 数据输入输出是否正确（空值/长文本/特殊字符）
- **P (Platform)**: 浏览器兼容性（本次以 Chrome 为主）
- **O (Operations)**: 操作序列是否正确（连续点击/快速切换）
- **T (Time)**: 响应时间是否合理，超时处理是否正确

## 规则 8: 协作方式

- Cascade 负责: 监控服务器日志、检查 API 响应、验证数据一致性、记录测试日志
- 用户负责: 在浏览器中操作前端页面、反馈 UI 显示结果、确认功能符合预期
- 每个测试步骤，Cascade 给出明确的操作指令，用户执行并反馈结果
