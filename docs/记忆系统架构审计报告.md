## 三、发现的 Bug 和断路点

### 🔴 BUG-1: ACE Reflector 参数不匹配（严重 — 功能完全失效）

**位置**: `brain_learning.py:25`

```python
await reflect_on_session(session_id, self._history, self.learning)
```

**函数签名** (`memory/sync.py:151`):
```python
async def reflect_on_session(messages: list[dict], tool_results=None, llm=None, ...)
```

**问题**:
- `session_id` (str) 传给了 `messages` (应为 list[dict])
- `self._history` (list[dict]) 传给了 `tool_results`
- `self.learning` (LearningAdapter) 传给了 `llm`

**影响**: 反思闭环完全断路。Brain 在工具调用后的自动经验提取**从未真正工作过**。`reflect_on_session` 收到 str 作为 messages，会遍历字符串的最后 30 个字符，产生垃圾或静默失败。

**修复**: 传递正确参数 + 将返回的 deltas 写入 store。

### 🔴 BUG-2: ACE Reflector 返回值被丢弃（严重）

**位置**: `brain_learning.py:25`

即使参数正确，`reflect_on_session` 返回 `list[dict]` (delta bullets)，但 `_ace_reflect_and_merge` 完全忽略了返回值——deltas **永远不会被 merge 到 MemoryStore**。

### 🟡 BUG-3: MemorySyncManager 从未接入（中 — 功能空置）

**位置**: `memory/sync.py:15-124`

`MemorySyncManager` 类（会话结束时自动提取关键信息）定义完整（~120行），有测试通过，但**从未在 startup.py 或 brain.py 中实例化**。`on_session_end()` 从未被调用。

**影响**: 会话结束时的自动记忆提取不工作。Memory Flush 部分补偿了这个功能（压缩前持久化），但 MemorySyncManager 的设计是在会话正常结束时触发，两者互补而非替代。

### 🟡 BUG-4: Markdown 启动时不索引（中 — 搜索不完整）

`markdown_store.index_to_store()` 仅作为 API 端点 `POST /api/memory/index` 存在，**启动时不自动调用**。这意味着：
- Memory Flush 写入的 `.md` 文件内容不会自动进入 MemoryStore 的 FTS5/向量索引
- `JSONMemoryAdapter.recall()` 虽然有 Markdown 搜索降级，但只是简单关键词匹配，不经过8阶段管线

### 🟡 BUG-5: BlockManager blocks 未注入 system prompt（中）

`BlockManager` 在 startup.py 初始化，`ensure_defaults()` 创建 persona/human/project 块，但 **brain.py `_build_messages()` 中没有任何代码读取 BlockManager 的 blocks 文本并注入 system prompt**。

BlockManager 目前仅通过 `MemoryToolAdapter` 作为 Brain 可调用的工具暴露（`core_memory_get/set/append`），不做直接注入。这与 Letta 的设计（blocks 自动注入 prompt 顶部）不一致。

### 🟢 BUG-6: MemoryCurator 仅服务旧适配器（低）

`memory_curator.py` 的 `curate()` 仅被 `JSONLessonsAdapter` 调用。当前运行时使用的 `MemoryStoreLearningAdapter` **没有集成 curator 的质量门控和组合删除**。MemoryStore 依赖 `_prune_harmful()` 做最低限度清理，但缺少：
- `should_add_lesson()` 质量门控
- `periodic_cleanup()` 周期性清理过期经验
- `history_cleanup()` 错位经验检测
- `quality_cleanup()` 指令型内容过滤

### 🟢 BUG-7: 文件监听器缺失（低）

GAP-3 报告中提到需要 `file_watcher.py`（对标 OpenClaw chokidar），但**从未创建**。用户编辑 `data/memory/*.md` 后不会自动重索引。

## 四、逻辑闭环分析

### ✅ 已闭环的数据流

| 闭环 | 入口 → 出口 | 状态 |
|------|-------------|------|
| **对话持久化** | user_input → save_message → sessions/*.json → get_context | ✅ |
| **经验学习** | _learn_pattern → merge_deltas → MemoryStore → get_lessons | ✅ |
| **经验检索** | get_lessons → search_hybrid(8阶段) → Core Block置顶 → prompt | ✅ |
| **ACE反馈** | mark_applied → increment_feedback → Importance Weight调权 | ✅ |
| **ACE清理** | _prune_harmful → harmful>helpful且>=3 → 自动删除 | ✅ |
| **Memory Flush** | compact前 → LLM提取 → .md文件 + MemoryStore(sessions) | ✅ |
| **Markdown搜索** | recall() → md_store.search() → 结果合并到检索结果 | ✅ |
| **工具观察** | execute() → ObservedToolAdapter → ToolObserver → observations | ✅ |
| **噪声过滤** | add() → is_noise() → 拒绝/寒暄/错误噪声不入库 | ✅ |
| **用户纠正→永久化** | _detect_and_learn → corrections≥2 → USER.md 写入 | ✅ |
| **向量回填** | backfill_embeddings() → 缺失embedding的条目渐进补充 | ✅ |

### ❌ 断路的数据流

| 断路 | 问题 | 影响 |
|------|------|------|
| **ACE Reflector** | 参数不匹配+返回值丢弃 | 工具调用后的自动经验提取完全失效 |
| **会话结束提取** | MemorySyncManager未接入 | 会话结束时不自动提取关键信息 |
| **Markdown→FTS5索引** | 启动时不调用index_to_store | .md文件内容不进入8阶段管线 |
| **Letta Blocks直注** | BlockManager未连到_build_messages | blocks内容不自动注入prompt |
| **Curator质量门控** | 未集成到MemoryStoreLearningAdapter | 经验库缺少组合删除策略 |
